# AS500-HMI

## CAN protocol

세 프로젝트(`AS500-HMI`, `AS500-interface`, `AS500-FND Driver`)의 전체 구성과
차량 CAN ID, payload, 단위, timeout, 보드별 책임은
[공통 CAN_PROTOCOL.md](../CAN_PROTOCOL.md)에 정리되어 있습니다.

`main/can/can_protocol.h`는 HMI 코드에서 사용하는 정의이며, 현재 구현과 헤더 간
차이는 통합 문서의 "현재 구현상 주의사항"을 확인하십시오.

ESP32-P4 기반 7인치(1024x600) HMI 프로젝트입니다.

## 기준 프로젝트

- 하드웨어, GPIO, LCD/BSP: `UWB-DW3000/esp32p4_controller`
- 애플리케이션 로직: `prj_ESPN32/esp32_as_interface_v3_48V`
- 보드: JC1060P470C_I_W, ESP32-P4 v1.x

DW3000 controller의 현재 작업 트리를 기준으로 복제했으며, 빌드 폴더와 원본 Git 이력은 포함하지 않았습니다. 기존 AS500-HMI 골격은 동일 상위 폴더의 `AS500-HMI_preclone_20260926_105412`에 보관되어 있습니다.

## 이식 원칙

P4 BSP, LCD/터치 초기화, GPIO 설정은 기준 프로젝트 구조를 유지합니다. DW3000 청소차 전용 로직은 단계적으로 분리하고, 기존 48V 인터페이스 프로젝트의 CAN, UART, ESP-NOW, 배터리, 릴레이 및 설정 로직으로 교체합니다.

## USB MP3 플레이어

USB 진단을 위해 반복 `CTRL`/`POSE` 출력(UART 및 USB Serial/JTAG)과 `CAN_RX`
프레임 로그를 임시로 끕니다. CAN 송수신/제어와 USB·오류 로그는 유지됩니다.
복원할 때는 `main/main.cpp`의 `kLogPeriodicControlPose`,
`main/can/as500_can.cpp`의 `kLogCanRxFrames`를 `true`로 변경합니다.

- JC1060P470C_I_W_Y-V1.0 회로도 기준 **USB3 (High speed USB) Type-C 포트**에
  데이터 연결이 가능한 젠더로 FAT32 USB 메모리를 연결합니다.
  USB2 (Full Speed USB)는 현재 MP3 Host 설정에서 사용하지 않습니다. USB Serial/JTAG
  로그/다운로드 포트와는 별개이며, USB 오디오 장치가 아니라 내장 ES8311
  코덱과 스피커로 출력합니다. NTFS/exFAT 및 USB 허브는 지원 대상이 아닙니다.
- 대시보드 MP3 타일을 짧게 누르면 재생/정지, 길게 누르면 기존 MP3 설정창을
  엽니다. 처음 조작할 때 USB 서비스가 시작됩니다. USB가 없으면 연결을
  기다리며, 연결하면 목록을 자동으로 읽습니다.
- 설정창은 볼륨(0~100), 순차/랜덤 반복 재생, 8곡씩 목록 이동과 곡 선택을
  제공합니다. 정지 상태에서 곡을 선택하면 선택만 변경되며, 타일로 재생합니다.
  재생 중에는 선택한 곡으로 전환합니다. USB 연결/제거 및 현재 곡 변경은
  열린 설정창에 자동 반영됩니다.
- 루트와 하위 2단계 폴더에서 `.mp3`를 대소문자 구분 없이 검색하고,
  경로순으로 정렬합니다. 최대 64곡, 전체 UTF-8 경로는 191바이트입니다.
  긴 파일명/한글 파일명은 FatFS LFN/UTF-8 설정을 사용하며 YCB로 표시합니다.
  제한을 넘긴 경로/곡은 로그에 안내합니다.
- 볼륨과 재생 모드는 변경이 멈춘 뒤 약 750ms 후 NVS에 저장하며 전원 켤 때
  복원합니다. 저장 전에 전원을 끄면 마지막 변경은 남지 않을 수 있습니다.
  곡 위치와 재생 ON 상태는 저장하지 않습니다.
- 파일 열기, 오디오 출력, USB 마운트, NVS 오류는 로그와 설정창 상태에
  표시합니다. USB 제거 시 재생 파일이 닫힌 뒤 언마운트합니다. 제거 후 다시
  연결하면 목록을 새로 읽고, 재생은 타일을 눌러 다시 시작합니다.
